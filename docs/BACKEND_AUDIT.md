# Backend audit

Reviewed `b407628` against the [API notes](API_NOTES.md). Scope covers the membership, settings, product and sale services, their authorization and response helpers, and their tests.

## 1. Owner-only operations

- **No owner-only operation was found callable by a `SALESPERSON`.** The shared guard requires an active `OWNER` membership in the target organization and throws `ACCESS_DENIED` otherwise. Mutations lock the organization and check the guard inside the transaction before running the write. [Owner guard and transaction](../apps/api/src/modules/access/organization-owner.ts#L14-L41)
- Membership directory reads call the guard directly. Invitation create, revoke and resend, member deactivate and reactivate, and store assignment and removal go through the guarded transaction. [Directory](../apps/api/src/modules/memberships/membership.service.ts#L49-L54), [invitation management](../apps/api/src/modules/memberships/membership.service.ts#L103-L164), [member management](../apps/api/src/modules/memberships/membership.service.ts#L219-L259)
- Trading settings reads call the guard directly. Cost visibility changes, purity add/deactivate/reactivate, and old-gold rate append use the guarded transaction. [Settings reads](../apps/api/src/modules/settings/settings.service.ts#L14-L19), [settings, purity and rate writes](../apps/api/src/modules/settings/settings.service.ts#L61-L115)
- An invited salesperson can accept a pending invitation for their verified email. Both assigned roles can read current rates through sale options. These are ordinary invite and sales workflows. [Invitation contract](API_NOTES.md#endpoints), [acceptance checks](../apps/api/src/modules/memberships/membership.service.ts#L167-L215), [sale options](../apps/api/src/modules/sales/sale.service.ts#L18-L49)

## 2. Acquisition-cost visibility

- **Product list** always omits `acquisitionCost` for both roles. The query and presenter use a fixed field list. [List query](../apps/api/src/modules/products/product.service.ts#L124-L142), [list fields](../apps/api/src/modules/products/product.presenter.ts#L9-L17), [list presenter](../apps/api/src/modules/products/product.presenter.ts#L46-L58)
- **Product detail** omits both cost and its currency for a salesperson when the flag is false. The query selects both fields only for an owner or when `salespersonCanViewAcquisitionCost` is true. The detail presenter includes the cost only when both fields are present. Product creation and photo confirmation also use the detail path. [Detail lookup](../apps/api/src/modules/products/product.service.ts#L35-L46), [detail selection](../apps/api/src/modules/products/product.presenter.ts#L19-L39), [serialization](../apps/api/src/modules/products/product.presenter.ts#L70-L89), [creation](../apps/api/src/modules/products/product.service.ts#L93-L96), [photo confirmation](../apps/api/src/modules/products/product.service.ts#L248-L272)
- **Sale create, replay, detail and list** always omit acquisition cost from the product snapshot for both roles. [Create response](../apps/api/src/modules/sales/sale.service.ts#L382-L387), [replay](../apps/api/src/modules/sales/sale.service.ts#L261-L276), [sale snapshot](../apps/api/src/modules/sales/sale.service.ts#L52-L95), [detail](../apps/api/src/modules/sales/sale.service.ts#L98-L115), [list](../apps/api/src/modules/sales/sale.service.ts#L205-L239)

## 3. Sale transaction and stock contention

- **One `ReadCommitted` transaction** covers the stock update, sale row, sold movement, each trade-in, its received-old-gold record and its receipt movement. A failure in any of those writes rolls back the entire transaction. [Transaction and claim](../apps/api/src/modules/sales/sale.service.ts#L250-L287), [sale and related writes](../apps/api/src/modules/sales/sale.service.ts#L333-L390)
- **Two distinct sales of the same product cannot both commit.** The organization row lock serializes the requests. The stock write is also conditional on `IN_STOCK`, so a competing sale after the first commit updates zero rows and returns `409 SALE_CONFLICT` on `productId`. [Row lock](../apps/api/src/modules/access/organization-owner.ts#L10-L12), [stock claim](../apps/api/src/modules/sales/sale.service.ts#L252-L287)

## 4. Idempotency

- The key is scoped by organization, store and actor. With current access, the same key and normalized input return the persisted sale and trade-ins through the sale presenter. Replay parses input using the stored currency. [Lookup, digest and replay](../apps/api/src/modules/sales/sale.service.ts#L250-L275)
- A different valid normalized input under that key returns `409 SALE_CONFLICT` on `idempotencyKey`. The digest hashes parsed input. Equivalent decimal spellings, omitted or empty trade-ins, and omitted or matching `expectedCurrency` produce the same digest. Validation runs first and may return its own error. [Digest check](../apps/api/src/modules/sales/sale.service.ts#L266-L275), [input normalization](../apps/api/src/modules/sales/sale-input.ts#L17-L50), [parsed fields](../apps/api/src/modules/sales/sale-input.ts#L82-L99)
- Concurrent identical requests serialize before lookup. Once the first commits, a waiting request that acquires the lock returns the same persisted sale without repeating any writes. If the first rolls back, the next request can create the sale. [Row lock](../apps/api/src/modules/access/organization-owner.ts#L10-L12), [lock and replay order](../apps/api/src/modules/sales/sale.service.ts#L252-L287), [isolation level](../apps/api/src/modules/sales/sale.service.ts#L382-L390)

## 5. Money and weight arithmetic

- **No JavaScript floating-point arithmetic on money or weights was found.** Product creation passes decimal strings through. Product weight, cost and settings rates are formatted from Prisma Decimal. [Product persistence](../apps/api/src/modules/products/product.service.ts#L76-L83), [product formatting](../apps/api/src/modules/products/product.presenter.ts#L46-L67), [rate formatting](../apps/api/src/modules/settings/settings.service.ts#L125-L134)
- Trade-in valuation multiplies decimal weight by the decimal rate. Settlement uses a 64-digit Prisma Decimal clone for summation, conversion, change and payout. It rounds the balance and converted tender half-up at the currency scale. [Trade-in calculation](../apps/api/src/modules/sales/sale.service.ts#L297-L321), [settlement](../apps/api/src/modules/sales/settlement.ts#L5-L45)

The current tests also cover underpayment and tender when no balance is due. Maximum supported sale and trade-in precision remains untested. [Product precision](../apps/api/test/products.integration.test.ts#L180-L216), [rate precision](../apps/api/test/settings.integration.test.ts#L141-L169), [underpayment](../apps/api/test/sales.integration.test.ts#L108-L121), [sale values](../apps/api/test/sales.integration.test.ts#L133-L147), [trade-in override](../apps/api/test/sales.integration.test.ts#L228-L244), [settlement tests](../apps/api/test/settlement.test.ts#L4-L70)
